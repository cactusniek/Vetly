🔴 TOP 15 THINGS TO FIX (IN PRIORITY ORDER)
================================================================================

1. HARDCODED API URL
   Location: src/global/api.ts (line 4)
   Issue: localhost:3000 hardcoded
   Fix Time: 5 min
   Impact: Can't deploy to production
   Solution:
     - Create .env.local with VITE_API_URL=http://localhost:3000
     - Create .env.production with VITE_API_URL=https://api.example.com
     - Replace hardcoded URL: import.meta.env.VITE_API_URL

2. ERROR LOGGING EXPOSED
   Location: src/global/api.ts (line 25)
   Issue: console.error sends full errors to production
   Fix Time: 30 min
   Impact: Sensitive data exposed in browser
   Solution:
     - npm install @sentry/react
     - init in main.tsx: Sentry.init({dsn: env.VITE_SENTRY_DSN})
     - Replace console.error with Sentry.captureException()

3. EVENT LISTENER MEMORY LEAK
   Location: src/components/Search.tsx (lines 44-49)
   Issue: Listeners accumulate on each mount
   Fix Time: 10 min
   Impact: Listeners not cleaned up properly
   Solution: Fix cleanup function to use removeEventListener

4. REMOVE UNNECESSARY "import React"
   Location: All component files
   Issue: React imported but never used
   Fix Time: 5 min
   Impact: Cleaner code (JSX auto-runtime handles it)
   Files: Header.tsx, Footer.tsx, Search.tsx, Medicine.tsx, Landing.tsx, Widget.tsx

5. NO ERROR BOUNDARY
   Location: Needs to be created
   Issue: App crashes silently
   Fix Time: 20 min
   Impact: Users see blank screen on errors
   Solution:
     - Create src/global/components/ErrorBoundary.tsx
     - Wrap <Router> with <ErrorBoundary>

6. UNTYPED ERROR HANDLING
   Location: Multiple files (Footer.tsx, Widget.tsx)
   Issue: catch(err) doesn't type err as unknown
   Fix Time: 10 min
   Impact: TypeScript best practices
   Solution: Use catch(err: unknown) and type guard

7. MISSING useCallback ON HANDLERS
   Location: src/components/Search.tsx
   Issue: Handlers recreated every render
   Fix Time: 15 min
   Impact: Unnecessary re-renders
   Solution: Wrap handleChange, handleSubmit in useCallback

8. EXPENSIVE RENDERS NOT MEMOIZED
   Location: src/components/Medicine.tsx
   Issue: parseDoeldieren() and parseWachttermijnen() called every render
   Fix Time: 10 min
   Impact: Performance hit
   Solution: Wrap in useMemo([doeldieren])

9. PROP DRILLING (4+ PROPS DOWN)
   Location: Widget.tsx → Search.tsx
   Issue: Too many props passed through hierarchy
   Fix Time: 30 min
   Impact: Hard to maintain, refactor difficult
   Solution: Use Jotai atoms for global search state (already installed)
     - Create atoms: searchQueryAtom, isLoadingAtom, etc.
     - Use useAtom() hook in components

10. NO PAGINATION (RENDERS 1000+ AT ONCE)
    Location: App-wide search results
    Issue: All results rendered in DOM
    Fix Time: 60 min
    Impact: Browser lag with large result sets
    Solution:
      - Add pagination (20 results per page) OR
      - Use react-window for virtual scrolling

11. MOBILE NAV STATE NOT RESET
    Location: src/components/Header.tsx
    Issue: Navigation menu stays open when navigating
    Fix Time: 10 min
    Impact: Mobile UX broken
    Solution:
      - useEffect(() => { setShowNav(false) }, [location])

12. PLACEHOLDER LINKS WITH href="#"
    Location: src/components/Footer.tsx (line 109), Widget.tsx (line 73)
    Issue: Dead links that go nowhere
    Fix Time: 5 min
    Impact: Looks broken
    Solution: Remove links or add real URLs

13. ANY TYPES IN API
    Location: src/global/api.ts
    Issue: med: any, Promise<any> - no type safety
    Fix Time: 15 min
    Impact: Runtime errors if API schema changes
    Solution: Replace with proper types (MedicineResults, MedicineProps)

14. NO LOADING SKELETON
    Location: Search results display
    Issue: DOM jumps when results appear
    Fix Time: 30 min
    Impact: Jarring UX
    Solution: Create skeleton component, show while loading

15. EMAIL VALIDATION MISSING
    Location: src/components/Footer.tsx (line 68)
    Issue: Accepts invalid emails, no error handling
    Fix Time: 10 min
    Impact: Invalid data submitted
    Solution:
      - Add email regex validation
      - Show error message if invalid
      - Handle duplicate emails


🟢 TOP 5 FEATURES TO ADD (IN PRIORITY ORDER)
================================================================================

1. ADVANCED FILTERS
   Effort: 60 min
   Add dropdowns for:
     - Delivery Status: Available / Archived / Suspended
     - Target Animal: Cow / Sheep / Pig / Poultry / Other
     - Dosage Form: Tablet / Injection / Powder / Solution
   Impact: Vets can find medicines instantly instead of scrolling 1000 items
   Why: Users ask for this more than anything else

2. SEARCH HISTORY (localStorage)
   Effort: 20 min
   Save last 5 searches in localStorage
   Show "Recent searches" dropdown in Search component
   Impact: Users search same meds repeatedly (saves 30 seconds per search)
   Bonus: Add "Clear history" button

3. SEARCH AUTOCOMPLETE/SUGGESTIONS
   Effort: 40 min
   Filter medicines list as user types (already has debounce)
   Show dropdown with matching medicines
   Sort by relevance (exact match first)
   Impact: Users don't know exact medicine names (like Google autocomplete)
   Bonus: Show icon + status next to each suggestion

4. FAVORITES/BOOKMARKS
   Effort: 30 min (localStorage) or 90 min (backend)
   Add heart icon on each medicine
   Save clicked medicines to localStorage
   Create "Favorites" page to bulk view
   Impact: Vets save common meds for quick access
   Bonus: Sync to backend if user logs in

5. RESPONSE CACHING
   Effort: 30 min
   Cache API responses in Jotai atom (Map<query, data>)
   Same search 10 times = 1 API call (after first)
   Add "Refresh" button to bypass cache
   Impact: Reduce API calls, faster search, better UX
   Bonus: Add cache timestamp ("Updated 2 hours ago")
